# 内置关键字与类型系统

本目录用于定义内置关键字、类型，以及字段和引用的语义。

## 已确认

- 区分实体类与值类型。
- 值类型属于 YAMBL 的 builtins，名称使用 `snake_case`，例如 `string`、
  `date` 和 `decimal`。
- 实体类型名称使用 `PascalCase`，例如 `Fund`、`HoldingEntry` 和 `Security`。
- 字段名称使用 `snake_case`，例如 `fund_id`、`net_asset` 和
  `holdings_entry_id`。
- 实体类型字段默认表示实体引用，无需额外的 `ref` 关键字。例如，
  `attr security: Security` 表示对证券实体的引用。
- 实体类型的集合表示实体引用的集合。例如，`HoldingEntry[]` 表示持仓条目
  实体引用的集合，不表示内嵌实体。
- 示例使用 `id 字段名: 类型` 声明实体标识字段，使用 `attr 字段名: 类型`
  声明普通属性，使用 `snapshot attr 字段名: 类型` 声明快照属性。
- `@temporal(as_of_date: date)` 描述对应快照属性的时间参数。不同属性的快照
  相互独立，即使它们使用相同的参数名称和类型。
- 当前模型描述不承担数据完整性等数据质量校验。示例中的类型和模式描述不意味着
  已有业务数据验证或 ID 生成行为。

## 内置值类型

当前已确认需要以下七种内置值类型：

| 类型 | 基本含义 |
| --- | --- |
| `bool` | 布尔值 |
| `string` | 字符串 |
| `integer` | 整数 |
| `float` | 浮点数 |
| `decimal` | 十进制数 |
| `date` | 日期 |
| `datetime` | 日期和时间 |

这些类型可直接用于字段或时间参数的类型位置，无需在业务模型中声明。
`decimal` 和 `string` 的参数形式见下文。其余参数规则、位宽、取值范围、时区、
字面量和可空性尚未确定，也尚未规定到数据库或 Python 类型的映射。

案例中的 `snowflake_id` 尚未纳入已确认的内置值类型清单，其定位仍待讨论。

## 已确认的类型参数

类型参数写在类型名后的方括号中，支持位置参数简写和命名参数写法。

| 类型 | 位置参数写法 | 等价的命名参数写法 |
| --- | --- | --- |
| `decimal` | `decimal[18, 4]` | `decimal[precision: 18, scale: 4]` |
| `string` | `string['[a-zA-Z0-9]{12}']` | `string[regex: '[a-zA-Z0-9]{12}']` |

`decimal` 的第一个位置参数为 `precision`，表示总十进制位数；第二个为
`scale`，表示小数位数。因此，上例描述总共 18 位数字，其中小数部分 4 位。
不带参数的 `decimal` 仍然有效，表示模型未指定精度和小数位数；这里不为它
隐式补充默认值。

`string` 的位置参数为正则表达式，对应命名参数 `regex`。例如，`string['']`
和 `string[regex: '']` 使用相同的空正则表达式参数。不带参数的 `string`
仍表示未指定正则表达式的字符串。

这些参数用于描述类型，不引入业务数据质量校验。正则表达式的匹配范围、转义
和具体语法方言，以及数值参数的合法范围，仍待确定。

## 暂缓定义

自定义值类型的声明方式暂不定义。此前讨论的 `type` 写法、名义类型与别名的
区分均未确认为语言规则。

## 待确定

- 实体身份的作用域、组合标识和标识继承规则。
- 值类型的相等规则。
- 字段的类型兼容规则，以及引用集合的顺序和重复值语义。
- 内置值类型的位宽、取值范围、时区、字面量和可空性。
- `decimal` 参数的合法范围、是否允许部分参数，以及位置参数与命名参数的
  混用、重复和顺序规则；其他内置类型是否支持参数。
- `string['[a-zA-Z0-9]{12}']` 的模式解释规则。
- `snowflake_id` 是内置值类型还是另行定义的值类型，以及它描述的值结构。
- 内置关键字与保留字清单。

[语法说明](../language/syntax.md)记录了 `entity`、`id`、`snapshot`、`attr`、
`@temporal`，以及案例使用的 `namespace` 写法。完整的关键字清单、注解机制
仍需确认；已确认的内置值类型见上表。
